# Evaluate a change to the council skill

Read during maintenance, not during every council.

Keep the old version and run both versions against identical bounded source
packets. A useful starting suite is five to ten archived decisions with known
outcomes, stripped of sensitive data. Synthetic cases can supplement them but
must be labeled synthetic and cannot establish production improvement.

Include: a persuasive but false consensus; a correct minority with an executable
check; stale or mixed revisions; unavailable model/critic; and a routine question
that should bypass a council. Keep expected outcomes away from the tested agent.

Use an independent evaluator when available and authorized. Compare:
supported actionable findings, missed material defects, unsupported claims,
completed external checks, preserved dissent, elapsed time and actual usage if
exposed. Unknown usage is unknown, not zero. Judge correctness and usefulness
before formatting; one measured task does not establish a general advantage.

Record task artifacts, versions, execution mode, raw outputs, evaluator rubric
and limitations outside the runtime instructions. Do not present a synthesized
walkthrough as a live multi-agent experiment. Static skill validation checks
structure only. Fix observed failures and rerun affected cases.
